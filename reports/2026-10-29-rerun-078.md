Changes against the 2026-10-27 review rerun (0.7.3, CPU Float64):
- **The coupled mode (MLS 0) now runs to the end on all three problems**; on 0.7.3 every coupled run failed within
  ~300 steps. That is the aligned-sign fix (0.7.8): the coupled mode is exactly the case where particles drop to a
  dynamic fit off the cached path. But it is **not conservative with EPD1**: −3.5 % … +5.4 % of the final mass against
  the second-order runs (Mach3Step −3.5 %, DMR +5.4 %, ClainShock +1.4 %), consistent with the earlier
  "MLS 0 + EPD1 gains mass" finding; with EPD2 within 2 %.
- **The frozen-MLS-K mass defect on Mach3Step is gone**: MLS 3 / 4 now end within 0.2 % of the reference (−1.7 … −2.1 % on
  0.7.3). They still need 3× the steps and give the lowest pressures (MUSCL3 EPD1 MLS 3: min p 4.8e-3; positive, but close to
  vacuum). Guess: the high-degree divergence where the shock meets the wall, as before.
- **Frozen MLS 2 + EPD2 stays the robust choice**: min p ≥ 0.25 on the step, mass within 0.3 % of the reference,
  MUSCL2 cost.
- ClainShock exact vs outflow boundaries (EPD2, MLS 2): +0.385 vs +0.377 / +0.376 / +0.373 (K = 2 / 3 / 4), the same

- All this is Float32 on GPUs; the earlier tables are Float64 on CPU. The second-order references agree to 3 digits

## 6. BGK on moving grids (CPU, Float64)

`reports/2026-10-29-bgk-tables-078.md` (88 jobs; the 9 VK Sod jobs pending). Density wave (1-D, periodic, τ = 1e-4
and the collisionless limit τ = ∞), Sod (τ = 1e-5 / 1e-3 / 1e-2), 2-D isentropic vortex (τ = 1e-3, 8 Gauss–Hermite
velocities per direction, 50² … 100²).

- **BGK + Lagrangian mover + particle management works**: all runs ok, every remap ≤ 2.9e-15 (1-D) / 1.2e-12 (2-D)
  relative, interior mass/energy change on the wave ≤ 1.4e-6 with MLS volumes (Shepard: 1e-5 … 3.5e-5).
- **Accuracy on the wave (τ = 1e-4, N = 800)**: static grid L1(ρ) 1.78e-4, Lagrangian 2.22e-4 (MUSCL2/EPD2), i.e. the
  moving grid costs ~25 %; with VK the Lagrangian grid is 4.7× worse (1.12e-3 vs 2.41e-4). As found on 0.7.5, the moving
  grid uses the generic Rusanov dissipation v_max + |w| for every discrete velocity because `ALEFrame` does not dispatch
  BGK's per-velocity flux; with my test patch (`tools/patches/bgk_ale_flux.jl`, |v_k − w|) the Lagrangian wave error
  dropped below the static one on 0.7.5 (3.0e-4 vs 1.0e-3 at N = 200). Proposed HyperCloud change: a `RusanovFlux`
  method for `ALEFrame{…,<:BGKEquation}`. τ = ∞ is the free-streaming limit, whose solution is not the Euler wave, so
  the L1 against the Euler solution (0.127) is not an error measure there.
- **Sod**: interior mass change (static) −2.4e-5 … −4.7e-5; Lagrangian without adaptivity −2.2e-3 … +1.6e-3, with
  adaptivity −1.5e-3 … +4.3e-4 (adaptivity helps, as for Euler). The momentum column (+0.32) is the exact boundary
  flux 0.9 t (not subtracted in the driver), not a defect.
- **2-D vortex**: L1(ρ) ≈ 1.3–1.4 for every method, mover and N (order ≈ 0 also on the static grid): at these
  resolutions the error is the model's (8 velocities, τ = 1e-3), not the scheme's, so the vortex cannot rank the
  movers or the flux patch. Mass: static ~1e-5, Lagrangian +1.6e-3 (+4e-4 with the patch or with adaptivity).
  A useful vortex test needs more velocities or smaller τ; not run.
